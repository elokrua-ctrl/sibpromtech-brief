# СИБПРОМТЕХ · Интерактивный стратегический бриф

Веб-приложение для стратегического интервью с руководством НПО «Сибирские Промышленные Технологии».
Руководитель отвечает на простые вопросы (10–15 минут), а приложение превращает ответы в:

- **«Ваши приоритеты развития СИБПРОМТЕХ»** — короткие итоги для заказчика;
- **стратегический отчёт для исполнителя** (10 разделов, с разделением «пожелание заказчика / исходные данные / рекомендация исполнителя»);
- **черновой план развития** на 0–3, 3–6 и 6–12 месяцев с зависимостями, объединением работ и объяснением, почему проект стоит в этом периоде.

Всё считается локально в браузере, без внешних API и серверов.

## Запуск

Нужен Node.js 20+.

```bash
npm install
npm run dev          # разработка: http://localhost:5173
npm run build        # сборка в dist/ для любого статического хостинга
npm run build:single # dist/index.html — всё приложение в одном файле
npm run preview      # посмотреть собранную версию
npm test             # проверки логики (условия, план, отчёты, экспорт, PDF)
npm run e2e          # сквозные сценарии в браузере (после npm run build:single)
npm run typecheck    # проверка типов
```

Для `npm run e2e` один раз установите браузер: `npx playwright install chromium`.

## Публикация

Приложение статическое — сервер не нужен.

**Самый простой способ — один файл.** `npm run build:single` → отправьте или выложите `dist/index.html`. Он открывается в любом современном браузере.

**По ссылке.** Подойдёт любой статический хостинг:

- **Netlify / Vercel**: подключите репозиторий, команда сборки `npm run build`, папка `dist`. Или перетащите папку `dist` в Netlify Drop.
- **GitHub Pages**: `npm run build`, опубликуйте содержимое `dist` (например, через GitHub Actions `actions/deploy-pages`). Пути относительные (`base: './'`), поэтому работает и в подпапке.
- **Свой сервер / Яндекс Object Storage / Selectel**: скопируйте содержимое `dist` в корень сайта или бакета со статическим хостингом.

Маршруты — через `#` (`#brief`, `#results`, `#view`), настраивать сервер под них не нужно.

## Важно про данные

- Пока человек заполняет бриф, ответы сохраняются в его браузере (localStorage): можно закрыть вкладку и продолжить позже.
- **Автоотправка в Telegram** (`src/config/delivery.ts`): после завершения брифа исполнителю в бота приходят сводка, PDF (отчёт + план) и JSON со всеми ответами. Если человек бросил на полпути и закрыл вкладку — приходит черновик (JSON). После изменения ответов приходит обновлённая версия. Успехом считается только ответ Telegram `ok`; при ошибке заказчик видит кнопку «Отправить ещё раз».
- Токен бота виден в коде страницы. Если бота начнут спамить — перевыпустите токен в @BotFather и обновите `delivery.ts`. Пустой токен или chat id отключают автоотправку: тогда на странице итогов остаются кнопки скачивания.
- JSON открывается в **режиме просмотра** (`#view`, ссылка внизу стартового экрана) — без опросника.

## Как устроен проект

```
src/
  data/                 ← всё, что можно править без изменения интерфейса
    questions.ts        этапы, вопросы, варианты, условия показа
    tools.ts            «инструменты» (сайт, ролик, каталог…) и когда они считаются выбранными
    projects.ts         проекты плана, зависимости, правила рекомендаций, объединения работ, темы для обсуждения
    kpi.ts              ожидания → измеримые критерии, сроки → горизонты плана
    types.ts            типы данных
  logic/
    flow.ts             условия, видимые вопросы, проверка ответов
    plan.ts             построение плана по прозрачным правилам
    report.ts           документы: итоги заказчика, отчёт исполнителя, план
    exporters.ts        текст, JSON (экспорт/импорт), CSV
    doc.ts              общая модель документа (экран, текст и PDF строятся из неё)
  pdf/                  генератор PDF без зависимостей (встроенный шрифт с кириллицей)
  storage/
    repository.ts       хранилище брифов (интерфейс + localStorage)
    download.ts         сохранение файлов и копирование
  components/           интерфейс
  config/brand.ts       фирменные цвета, название, пути к логотипу
tests/                  проверки логики
scripts/e2e.mjs         сквозные сценарии в браузере
```

### Как поменять вопросы

Откройте `src/data/questions.ts`. У каждого вопроса: `type` (`single`, `multi`, `text`, `rank`, `perItem`), `options`, флаги `allowOther` / `allowUnknown` / `allowComment`, `maxSelect`, `optional` и условие показа `showIf`, например:

```ts
showIf: { q: 's_need', any: ['main', 'later', 'improve'] }
```

Доступные условия: `any`, `none`, `anyReal`, `answered`, `countGte`, `tool`, `toolsCountGte`, а также `all` / `some` / `not`.
После правок запустите `npm test` — первый тест проверяет, что все ссылки на вопросы, варианты и проекты существуют.

### Как устроены рекомендации и план

1. Проект попадает в план, если заказчик выбрал его инструмент, или сработало правило `recommendWhen` (причина пишется в карточке).
2. Базовые работы (аудит, тексты, съёмка) добавляются, когда от них зависят другие проекты. Например, сайт, ролик и каталог зависят от одной съёмки — план это показывает и предлагает объединить.
3. Период — из ответа о сроках; без срока — 0–3 мес. для трёх главных задач, иначе стандартный для проекта.
4. В первом периоде не больше 4 проектов по выбору заказчика (`H1_CAPACITY` в `kpi.ts`).
5. Зависимость ставится не позже зависимого проекта.
6. Стоимость не рассчитывается: каждый проект помечен «требуется отдельная смета», разовые и ежемесячные работы разделены.

Правила перечислены и в самом плане — их видит и заказчик, и исполнитель.

## Логотип и шрифт

Файлы брендбука в проект не передавались, поэтому логотип не подставлен и не нарисован заново — в шапке выводится название текстом. Как подключить оригинальный логотип: `public/brand/README.md`. Фирменный шрифт задаётся переменной `--font-brand` в `src/styles.css`. Цвета — по брендбуку: `#07141B`, `#2D4056`, `#C7181C`, `#D9D9D9`, белый.

PDF использует шрифт Liberation Sans (лицензия SIL OFL), встроенный в `src/pdf/fonts`.

## Как добавить сервер и анализ нескольких брифов

Архитектура к этому готова:

1. **Хранение.** `src/storage/repository.ts` описывает асинхронный интерфейс `BriefRepository` (`loadCurrent`, `saveCurrent`, `list`…). Напишите `ApiBriefRepository` с теми же методами (например, `POST /api/briefs`, `GET /api/briefs`) и подставьте его вместо `LocalBriefRepository`. Интерфейс менять не нужно.
2. **Формат данных.** Бриф — это `BriefRecord` (`id`, даты, статус, автор, ответы) со `schemaVersion`. Экспорт JSON дополнительно содержит снимок вопросов и производные данные (`derived.tools`, `derived.top3`, `derived.projects`) — их удобно агрегировать.
3. **Анализ нескольких брифов.** Режим просмотра (`src/components/ViewMode.tsx`) уже работает с одним брифом из файла. Панель сравнения — это список из `repository.list()` (или нескольких JSON) и сводка по `derived`: какие инструменты выбирали чаще, где расходятся приоритеты разных руководителей.
4. **Отправка.** Когда появится сервер, добавьте кнопку «Отправить исполнителю» и подтверждение реального ответа сервера. Пока сервера нет, приложение честно говорит, что данные нужно выгрузить и передать вручную.
